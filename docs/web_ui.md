# คู่มือหน้าเว็บ / Web UI guide

เปิดเบราว์เซอร์ (มือถือหรือคอมพิวเตอร์ที่อยู่ในเครือข่ายเดียวกัน) แล้วเข้า

```
http://<ไอพีของเครื่องหุ่นยนต์>:8080
```

ไม่ต้องติดตั้งแอป ไม่ต้องต่ออินเทอร์เน็ต หน้าเว็บทำงานได้ทั้งหมดในเครื่อง

## ใครเปิดจากไหนได้บ้าง

| เครื่อง | ทำอะไร | คุมหุ่นได้ไหม |
|---|---|---|
| คอม Ubuntu ที่ต่อกับหุ่น (server) | `ros2 launch gps_localize bringup.launch.py` | ได้ — เป็นตัวเซิร์ฟเวอร์ |
| มือถือ / แท็บเล็ต / โน้ตบุ๊ก ใน Wi-Fi เดียวกัน | เปิดเบราว์เซอร์ไปที่ไอพีของ server | **ได้เต็มรูปแบบ** |
| คอม Windows ที่ไม่มี ROS | `webapp\run_windows.bat` | **ไม่ได้** ดูอย่างเดียว |

หน้าเว็บออกแบบให้ใช้บน **มือถือ** เป็นหลัก: ปุ่มใหญ่กดง่ายด้วยนิ้วโป้ง
ตารางเลื่อนในตัวเอง ไม่ล้นจอ ใช้ได้ทั้งแนวตั้งและแนวนอน และรองรับโหมดมืด/สว่างตามเครื่อง
บน iPhone/Android กด "เพิ่มไปยังหน้าจอโฮม" จะเปิดแบบเต็มจอเหมือนแอปได้เลย

เปิดพร้อมกันได้หลายเครื่อง (ค่าเริ่มต้น 8 เครื่อง) ทุกเครื่องเห็นข้อมูลชุดเดียวกัน
และ **ทุกเครื่องกดปุ่มสั่งงานได้** — ตกลงกันหน้างานว่าใครเป็นคนคุม
ส่วนปุ่มหยุดฉุกเฉิน กดได้จากทุกเครื่องเสมอ (ตั้งใจให้เป็นแบบนั้น)

## โปรแกรมดูอย่างเดียวบน Windows / Ubuntu

โฟลเดอร์ `webapp/` คือหน้าเว็บเดียวกันที่รันได้โดยไม่ต้องมี ROS และไม่ต้องมีหุ่น

* Windows: ดับเบิลคลิก `webapp\run_windows.bat` (ใช้ `exe\GPS_Localize_Viewer.exe` ไม่ต้องลง Python)
* Ubuntu: `webapp/run_ubuntu.sh`

จะขึ้นแถบเหลือง **“โหมดสาธิต”** และเด้งข้อความเตือนตอนเปิด

**ปุ่มทุกปุ่มกดได้จริง แต่สั่งได้แค่ “หุ่นจำลอง” บนแผนที่** — ขับด้วย W A S D,
กดหมุน 90°, คลิกแผนที่แล้วสั่ง “ไปที่นี่เลย”, ตั้งตำแหน่งเริ่มต้นแบบลากลูกศร,
กดหยุดฉุกเฉิน ทั้งหมดเห็นผลทันทีในหน้าจอ เหมาะกับการฝึกใช้งานและสอนลูกค้า
โดยไม่ต้องมีหุ่นจริง (โปรแกรมนี้ไม่มี ROS และไม่มีวิทยุ จึงไปถึงหุ่นจริงไม่ได้เลย)

ตัวเลขทุกตัวมีคำว่า SIMULATED กำกับ · เปิดด้วย `--no-demo` ถ้าอยากได้หน้าจอเปล่า
และล็อกปุ่มทั้งหมด

ใช้แก้ไฟล์ตั้งค่า/จุดหมายไว้ล่วงหน้าได้ด้วย แล้วคัดลอกไฟล์จาก
`webapp/exe/settings/` ไปไว้ที่ `~/.gps_localize/` บนเครื่องหุ่น
ในแถบเหลืองมีช่องใส่ไอพีของหุ่นยนต์ กดปุ่มแล้วข้ามไปหน้าจริงได้ทันที

## แถบบน / Top bar

| สิ่งที่เห็น | ความหมาย |
|---|---|
| **เชื่อมต่อ** | สถานะการเชื่อมต่อระหว่างเบราว์เซอร์กับหุ่นยนต์ ถ้าเป็นสีแดง = หลุด หุ่นจะหยุดเองภายใน 1 วินาที |
| **ESP32** | อายุข้อมูลล่าสุดจากบอร์ด ถ้าเกิน 1.5 วินาที = บอร์ดไม่ส่งข้อมูล และจะบอกว่าขาดไปนานเท่าไร |
| **loop** | เวลาที่ลูปควบคุมใช้ต่อรอบ คาบคือ 10 ms · เขียว < 6 ms · เหลือง < 9 ms · แดงคือใกล้หมดเวลา<br><small>The first thing that shows the firmware is in trouble: it went from 4 ms to 178 ms in one session while every other number on this bar stayed put.</small> |
| **GPS** | จำนวนดาวเทียมและค่า HDOP (ยิ่งน้อยยิ่งแม่น) |
| **แบตเตอรี่** | แรงดันแบตจริงจาก INA226 · เขียว > 11.7 V · เหลือง > 11.4 V · แดง < 11.199 V บน 3S (ตัดมอเตอร์) |
| **สัญญาณ** | ความแรงสัญญาณ Wi-Fi **ที่ตัวหุ่น** (ไม่ใช่ที่เครื่องที่เปิดเว็บอยู่) · เขียว ≥ −70 dBm · เหลือง ≥ −80 · แดงต่ำกว่านั้น · “ไม่ต่อ” = บอร์ดยังไม่เกาะ AP เลย<br><small>The number that separates "the firmware has stopped" from "it drove out of range". A phone can sit beside the router while the robot is at the far end of the garden, so the browser's own signal says nothing about the link that matters.</small> |
| 🔴 **หยุดฉุกเฉิน** | สั่งหยุดทันที ล็อกไว้จนกว่าจะกด “ปลดล็อก” |
| **ปลดล็อก** | ปลดการหยุดฉุกเฉิน (กดได้เมื่อมีการล็อกอยู่เท่านั้น) |

> ปุ่มหยุดฉุกเฉินบนเว็บคือ *ชั้นที่ 5* ของระบบความปลอดภัย ปุ่มเห็ดสีแดงบนตัวหุ่นยังเป็นตัวตัดไฟจริงเสมอ

## แถบล่าง — ข้อมูลสดหรือค้าง / Status bar

ด้านล่างสุดของทุกหน้ามีจุดสีเล็ก ๆ บอกความสดของข้อมูล — **สำคัญมาก** เพราะตัวเลขที่ค้างอยู่
หน้าจอดูเหมือนของจริงเสมอ

| จุด | ข้อความ | หมายความว่า |
|---|---|---|
| 🔵 กะพริบ | กำลังเชื่อมต่อ | ยังไม่ได้รับข้อมูลชุดแรก |
| 🟢 | ข้อมูลสด / live | ปกติ ข้อมูลใหม่กว่า 2 วินาที |
| 🟡 | ข้อมูลค้าง / stale + “ล่าสุด N วินาทีที่แล้ว” | ตัวเลขบนจอจะจางลงและมีเครื่องหมาย ⏱ กำกับ **อย่าเชื่อว่าเป็นค่าปัจจุบัน** |
| 🔴 | ไม่ได้เชื่อมต่อ / offline | ขาดเกิน 10 วินาที มีปุ่ม **ลองใหม่ / Retry** บนแถบแดง |

ถ้าไม่มีข้อมูล หน้าจอจะไม่ปล่อยว่าง ๆ แต่จะบอกว่ากำลังรออะไรอยู่ เช่น
แผนที่ยังไม่มีจุดอ้างอิง หรือยังไม่มีจุดหมายในรายการ พร้อมบอกวิธีเริ่ม

## หน้าหลัก / Dashboard

* **ความเร็ว / ทิศทาง** — ค่าที่หุ่นคิดได้จริง (IMU + GPS) ทิศ 0° = ทิศเหนือ
* **ละติจูด / ลองจิจูด** — พิกัดปัจจุบัน ก็อปไปเปิดใน Google Maps ได้เลย
* **ล้อ** — รอบและความเร็วล้อซ้าย/ขวา คำนวณจาก IMU และจากแรงดัน/กระแสมอเตอร์ (ไม่มี encoder ที่ล้อ)
* **ไฟฟ้า** — แรงดัน/กระแส จากเซ็นเซอร์ INA226 ทั้ง 4 ตัว (แบต · มอเตอร์ A · มอเตอร์ B · พัดลม)
* **หน่วยความจำว่าง** — RAM ที่เหลือบน ESP32 ค่านี้ควร “นิ่ง” ถ้าค่อย ๆ ลดลงเรื่อย ๆ แปลว่ามีปัญหา ให้แจ้งผู้ดูแล
* **ภารกิจ** — สถานะ (IDLE / RUNNING / PAUSED / BLOCKED / ALIGN / FINISHED) จุดหมายปัจจุบัน ระยะ และเวลาที่เหลือ
  · **ALIGN** = ถึงจุดแล้ว กำลังหมุนอยู่กับที่ให้หันตามทิศที่ตั้งไว้ของจุดนั้น
* **ขับเอง** — กดปุ่มลูกศรค้างไว้เพื่อขับ ปล่อยแล้วหยุดทันที
  (แป้นพิมพ์: W A S D หรือปุ่มลูกศร · **Space = หยุดทุกอย่างทันที**)
* **ความเร็ว** — มีตัวเดียว หน่วยเป็น m/s จริง ๆ กดปุ่ม **ช้า 0.10 · ปกติ 0.18 · เร็ว 0.30**
  หรือปรับละเอียดด้วย + / − (ทีละ 0.02 m/s) ตัวเลขใหญ่ด้านบนคือความเร็วที่หุ่นจะวิ่งจริง
  ไม่มีตัวคูณซ่อนอยู่ · กด **จำค่านี้ไว้** เพื่อบันทึกเป็นค่าเริ่มต้นถาวร
  (โหมดละเอียดมี + / − ของความเร็วเลี้ยว ทีละ 5 °/s ด้วย)
* **หมุนตามองศา** — กด `90° ↻` `180°` หรือพิมพ์องศาเอง หุ่นจะหมุนอยู่กับที่แล้วหยุดเอง
* **หันไปทางทิศ** — กด N / E / S / W หุ่นจะหมุนไปทางนั้น
  ทั้งสองอย่างนี้ **ใช้ในร่มได้ ไม่ต้องมี GPS** (ใช้เข็มทิศกับไจโร) เหมาะกับการทดสอบบนโต๊ะหรือในห้อง
* **เซ็นเซอร์** — ป้ายสีบอกว่าตัวไหนยังดีอยู่ ถ้าตัวใดเสีย ระบบจะสลับไปใช้ตัวที่เหลือให้เอง
  และบอกว่าตอนนี้ทิศทางอ้างอิงจากอะไร (เข็มทิศ / GPS / ไจโรอย่างเดียว)

ปุ่มภารกิจ:

| ปุ่ม | ทำอะไร |
|---|---|
| เริ่ม / START | เริ่มวิ่งตามรายการจุดหมายจากจุดแรก |
| พัก / PAUSE | หยุดชั่วคราว จำจุดเดิมไว้ |
| ไปต่อ / RESUME | วิ่งต่อจากจุดที่ค้างไว้ |
| ข้ามจุด / NEXT | ข้ามจุดปัจจุบันไปจุดถัดไป |
| จบภารกิจ / STOP | หยุดและกลับไปสถานะว่าง |

## แผนที่ / Map

แผนที่ในเครื่อง ไม่ต้องใช้อินเทอร์เน็ต แสดงเป็นระยะทางจริง (เมตร)

* ▲ เขียว = ตัวหุ่น หัวลูกศรคือทิศที่หันอยู่
* ● ฟ้า = จุดหมาย · ● เหลือง = จุดที่กำลังมุ่งหน้าไป
* ✛ แดง = จุดที่เพิ่งเลือกไว้
* เส้นจาง = เส้นทางที่ผ่านมา (เก็บล่าสุด 300 จุด)
* **พอดีจอ** = ซูมให้เห็นทุกจุด · **ล้างเส้นทาง** = ลบรอยทางเดิม
* **จอยสติ๊ก / Joystick** ในหน้าหลัก — ลากเพื่อเดินหน้าและเลี้ยวพร้อมกัน ปล่อยแล้วหยุด
  <small>The arrow pad sends forward OR turn, one at a time, so an arc had to be
  driven by alternating two buttons - a zig-zag rather than a curve. The
  firmware always accepted both in the same command; the joystick is the control
  catching up. Keyboard too: W and A held together is forward-and-left, where it
  used to replace one with the other.</small>
* ซูมได้ตั้งแต่ประมาณ **1000 กม.** จนถึง **1 เมตร** · เส้นตารางใช้ขั้น 1-2-5 เริ่มที่ 0.1 ม.
  จึงวัดในลานแคบ ๆ หรือหน้าหอพักได้จริง
  <small>The grid used to start at 5 m and double, so the finest step it could
  draw was 5 m and in practice it sat at 20 — useless anywhere everything worth
  measuring is smaller than a car. Tile requests stop at zoom 19, which is what
  OpenStreetMap and Esri actually publish; past that the last real tiles are
  drawn larger rather than the map going blank, which is what used to happen and
  read as a broken satellite view.</small>

### เลื่อนดูพิกัด และเลือกจุดบนแผนที่

**เลื่อนเมาส์ (หรือลากนิ้ว) ไปตรงไหนก็ได้** มุมซ้ายบนจะบอกทันที

```
13.7367920, 100.5232104
ระยะ 12.4 m · ทิศ 137° · หมุนขวา 25°
```

คือ ละติจูด/ลองจิจูดของจุดนั้น · ระยะจากหุ่นถึงจุดนั้น · ทิศที่ต้องมุ่งหน้า
(0° = เหนือ) · และต้องหมุนตัวไปกี่องศาจากที่หันอยู่ตอนนี้

**คลิกหรือแตะ** จะปักหมุด ✛ และเปิดเมนูให้เลือก

| เมนู | ทำอะไร |
|---|---|
| **ไปที่นี่เลย / Go here** | สั่งหุ่นวิ่งไปจุดนั้นทันที เป็นเป้าหมายครั้งเดียว **ไม่ถูกบันทึกลงรายการ** ถึงแล้วหยุดเอง |
| **เพิ่มเข้ารายการ / Add to list** | บันทึกเป็นจุดหมายต่อท้ายรายการ (บันทึกให้เลย ไม่ต้องกด SAVE ซ้ำ) |
| **คัดลอกพิกัด / Copy** | คัดลอกไปวางใน Google Maps หรือ LINE ได้ |
| **ปิด / Close** | ปิดเมนู (กด Esc หรือคลิกที่อื่นก็ได้) |

“ไปที่นี่เลย” ใช้เงื่อนไขความปลอดภัยชุดเดียวกับภารกิจปกติทุกอย่าง —
ถ้ากดหยุดฉุกเฉินอยู่ หรือสัญญาณ GPS ไม่ดีพอ หุ่นจะไม่วิ่ง และจะบอกเหตุผลให้
กด **จบภารกิจ / STOP** เพื่อยกเลิกระหว่างทาง

ถ้ายังไม่เคยจับสัญญาณ GPS แผนที่ยังไม่มีจุดอ้างอิง จะขึ้นว่า “รอสัญญาณ GPS”
และยังเลือกจุดไม่ได้

### ตั้งตำแหน่งเริ่มต้น เมื่อไม่มี GPS (เหมือน 2D Pose Estimate ของ RViz/Nav2)

ใช้ตอนทดสอบในร่ม หรือเป็นตัวสำรองเมื่อ GPS หาย — **บอกหุ่นเองว่าอยู่ตรงไหนและหันไปทางไหน**

1. กดปุ่ม **📍 ตั้งตำแหน่งเริ่มต้น / Set start pose** (ปุ่มจะเป็นสีเขียว = พร้อมใช้)
2. **กดค้าง** บนแผนที่ตรงตำแหน่งที่หุ่นอยู่จริง
3. **ลาก** ไปทางที่หัวหุ่นหันอยู่ จะเห็นลูกศรเขียวและองศาแบบเรียลไทม์
4. **ปล่อย** — ระบบจะตั้งทิศให้บอร์ด ESP32 ทันที และตั้งจุดอ้างอิงให้แผนที่

ปุ่มนี้ต้องกดเปิดก่อนทุกครั้ง (ใช้ได้ครั้งเดียวแล้วปิดเอง) เพราะเป็นการ
“บอกความจริงใหม่” ให้หุ่น จึงไม่ให้เกิดขึ้นโดยบังเอิญ

หลังตั้งแล้ว ถ้าไม่มี GPS หุ่นบนแผนที่จะกลายเป็น **ลูกศรกลวงสีส้ม** พร้อมข้อความ
“ประมาณจากล้อ/IMU (ไม่มี GPS)” — เตือนว่าเป็นค่าประมาณ ไม่ใช่พิกัดจริงจากดาวเทียม
ค่านี้จะคลาดเคลื่อนขึ้นเรื่อย ๆ หลายเมตรต่อนาที

**ถ้าจะให้วิ่งตามจุดหมายโดยไม่มี GPS จริง ๆ** (ทดสอบเท่านั้น) ต้องเปิด
`nav.allow_dead_reckoning: true` ในหน้าตั้งค่า → การเดินทาง ค่าปกติปิดไว้

## จุดหมาย / Waypoints

วิธีที่ง่ายที่สุด: ขับหุ่นไปยืนตรงจุดที่ต้องการ แล้วกด **“เพิ่มจุดที่นี่”**
ระบบจะบันทึกพิกัดปัจจุบันให้อัตโนมัติ

หรือพิมพ์เอง: คัดลอกพิกัดจาก Google Maps (เช่น `13.736717, 100.523186`)
มาใส่ช่อง Latitude และ Longitude

**ช่อง ทิศ / Face** — ใส่องศาเข็มทิศ 0–359 ถ้าต้องการให้หุ่น **หันไปทางนั้นเมื่อถึงจุด**
เว้นว่างไว้ = หันทางไหนก็ได้ (ปกติใช้แบบนี้)

หุ่นจะ **ถึงจุดก่อน แล้วค่อยหมุนอยู่กับที่** ไม่ใช่หมุนระหว่างวิ่งเข้าหาจุด
เพราะหุ่นคันนี้เลี้ยวด้วยการวิ่ง ถ้าพยายามเข้าจุดพร้อมหันให้ถูกทิศ เส้นทางจะโค้ง
แล้วไปจอดผิดที่ ถ้าหมุนไม่สำเร็จภายใน `align_timeout_s` ระบบจะไปจุดถัดไปต่อ
พร้อมเขียนบันทึกไว้ — เพราะหุ่น **ถึงจุดแล้ว** การหยุดทั้งภารกิจเพราะหันผิดไปไม่กี่องศา
แย่กว่า

| ปุ่ม | ทำอะไร |
|---|---|
| ไป | สั่งให้จุดนี้เป็นเป้าหมายทันที |
| ↑ ↓ | สลับลำดับการวิ่ง |
| ✕ | ลบจุดนั้น |
| **บันทึก / SAVE** | ต้องกดทุกครั้ง ไม่กด = ยังไม่บันทึก |

ไฟล์จริงอยู่ที่ `~/.gps_localize/waypoints.yaml`

## ตั้งค่า / Settings

แก้ตัวเลข → กด **บันทึก** → มีผลทันที ไม่ต้องแฟลชบอร์ดใหม่ ไม่ต้องรีสตาร์ต

แยกเป็นกลุ่มละเรื่อง กดเลือกกลุ่มด้านบน แล้วแก้เฉพาะเรื่องที่ต้องการ

| กลุ่ม | ใช้ทำอะไร | ไฟล์ |
|---|---|---|
| การเดินทาง | ความเร็ว ระยะที่ถือว่าถึงจุดหมาย เงื่อนไขคุณภาพ GPS | `nav.yaml` |
| PID ควบคุม | ค่าคุมทิศทางและความเร็วในบอร์ด ESP32 ([tuning.md](tuning.md)) | `pid.yaml` |
| มอเตอร์ | เวลาเร่ง/ชะลอ และค่าไฟฟ้าของมอเตอร์ (Ke, R) | `motor.yaml` |
| เซ็นเซอร์/ทิศทาง | ใช้เข็มทิศหรือ GPS หาทิศ ค่าปรับต่าง ๆ | `estimator.yaml` |
| ตัวหุ่นยนต์ | ขนาดล้อ ระยะห่างล้อ ความเร็วสูงสุด | `robot.yaml` |
| ความปลอดภัย | ความถี่สัญญาณหัวใจ เวลาที่ยอมให้เน็ตหลุด | `safety.yaml` |
| เว็บ | พอร์ต ความถี่อัปเดตหน้าจอ ความเร็วตอนขับเอง | `web.yaml` |

**`reverse_allowed` has been removed.** It sat in `nav.yaml` and on this page and was read by no code at all, so toggling it changed nothing. `heartbeat_rate_hz`, `manual_repeat_ms` and `trail_points` had the same problem and were wired up instead: the browser now takes all three from the robot rather than from hardcoded numbers.

**ถ้าแก้จนหุ่นวิ่งแปลก** กดปุ่ม **คืนค่าโรงงาน / FACTORY RESET** ของกลุ่มนั้น
ค่าจะกลับไปเป็นค่าที่ติดมากับเครื่อง

ล็อกไม่ให้ใครแก้: ตั้ง `web.allow_config_edit: false` แล้วหน้าตั้งค่าจะกดบันทึกไม่ได้

## ปรับเทียบ / Calibration

ปรับเทียบทุกอย่างรวมอยู่หน้านี้หน้าเดียว ไม่ต้องใช้สาย ไม่ต้องพิมพ์คำสั่ง
All of the calibration in one place — no cable, no terminal.
Full instructions: [calibration.md](calibration.md).

| ขั้น | ทำอะไร | เสร็จเมื่อ |
|---|---|---|
| 1 · เข็มทิศ / Compass | กดเริ่ม หมุนหุ่นช้า ๆ ครบ 1 รอบ กดบันทึก | แถบสีเขียว (สวาดครบ 3/4 วง) |
| 2 · ไอเอ็มยู / IMU | กดเริ่ม ขยับเป็นเลขแปดช้า ๆ ห่างจากมอเตอร์ กดบันทึก | ไฟ 4 ดวงถึงดวงที่ 2 (accuracy ≥ 2) |
| 3 · ล้อ / Wheels | วัดด้วยตลับเมตร แล้วกรอกในหน้าค่าในบอร์ด | — |
| 4 · มอเตอร์ / Motor model | อ่านค่าไฟสด ๆ แล้วปรับ `motor.ke` และ `motor.resistance` | รอบจากไฟฟ้าตรงกับที่วัดได้ |
| 5 · ตั้งศูนย์ / Zero | ให้จุดที่ยืนอยู่เป็น 0,0 | ทันที |

ขั้น 1 กับ 2 พอสำหรับการขับปกติแล้ว ขั้นอื่นทำเมื่ออยากให้แม่นขึ้น ·
Steps 1 and 2 are enough to drive; the rest is accuracy and can wait.

**แถบความคืบหน้าขยับเฉพาะตอนหุ่นหมุนจริง** — นับจำนวนตัวอย่างไม่ได้บอกอะไร
เพราะจอดนิ่ง ๆ ก็เก็บตัวอย่างได้เป็นพัน ·
The progress bar only moves while the robot really turns. Sample count would
not do: standing still piles up thousands of samples and calibrates nothing.

**เข็มทิศตายหลังปรับเทียบ ให้กด ล้างค่า / Clear.** ค่าที่ผิดแย่กว่าไม่ปรับเลย
เพราะระบบตรวจสนามแม่เหล็กจะเริ่มทำงานแล้วปฏิเสธทุกค่าที่อ่านได้ ·
A stored calibration switches on the magnetic-disturbance check, so a bad one
rejects every reading and the compass goes silently dead. Clear is the way out.

## เมื่อเน็ตหลุด / When the network drops

1. หน้าเว็บขึ้นแถบแดง “การเชื่อมต่อหลุด”
2. เบราว์เซอร์หยุดส่งสัญญาณหัวใจ → ตัวเฝ้าระวังหยุดส่งต่อให้ ESP32
3. ภายใน 0.6 วินาที เฟิร์มแวร์เบรกมอเตอร์เอง ไฟ LED แดงกะพริบถี่
4. เมื่อเน็ตกลับมา หุ่น **ไม่วิ่งต่อเอง** ต้องกด “เริ่ม” หรือ “ไปต่อ” ใหม่เท่านั้น

พฤติกรรมนี้ตั้งใจให้ปลอดภัยไว้ก่อน — ถ้าต้องการให้หุ่นวิ่งต่อได้แม้ปิดหน้าเว็บ
ให้ปิด `safety.require_web_heartbeat` (ไม่แนะนำ)

## Opening the UI without knowing an IP address

    http://gps-robot-web.local:8080

Published by `gps_localize_mdns.service`, which re-checks the address and
republishes when it changes - so the name keeps working after the PC moves
network, which a written-down IP does not. Needs `avahi-daemon` and
`avahi-utils`; the installer says so if they are missing.

The name uses **hyphens, not underscores**. `gps_robot_web.local` looks more
natural and does not resolve: RFC 1123 does not allow an underscore in a
hostname. avahi will publish one, and then browsers and system resolvers refuse
to look it up - correct everywhere except where it is typed.

The **Help** tab carries a QR of that URL for phones, the addresses behind it,
and the order the robot uses to find this PC. Android below 12 has no mDNS in
the browser, so the IP address is shown alongside for those.
